# Team requests implementation

Implemented in `D:\mailflare` on 7 October 2026 and deployed to production after the user's explicit deployment request. No failed delivery was replayed and no real test email was sent; test sends used a controlled provider mock. The original plan remains unchanged.

## Changes

- Active administrators use one installation-wide configured-domain policy for account options and provisioning. Ordinary, disabled, pending, and archived users are rejected. User/mailbox reservations are atomic, conflicts return 409, and creator attribution and existing activation/MFA/lifecycle behavior remain intact. Domain ownership is unchanged.
- Active users can create personal tasks and in-app reminders without a mailbox. Record ownership, assignment permissions, completion, snooze, and retry deduplication remain enforced. Disabled/inactive users and cancelled imported meetings are excluded from reminder dispatch. The local fallback timezone is Africa/Nairobi; instants remain in UTC.
- The composer and both send APIs share limits: ten attachments, 3 MiB combined raw attachments, an 8 MiB request cap, and a conservative 5 MiB final message budget. Final validation includes signature assets, body/header encoding, MIME/base64 overhead, and threading headers. The provider budget is checked again before submission. Size/count failures return 400/413.
- Multipart sends retain the compatible endpoint. Actual upload-byte progress, a 90-second browser deadline, a 45-second provider confirmation deadline, and read-only status lookup prevent indefinite loading. Queue acceptance, sending, provider acceptance, failure, and unknown outcomes have distinct labels. Bounded polling never resubmits. Undo uses the server deadline; idempotency and existing queue/DLQ policies remain in force. Ambiguous provider outcomes offer no blind resend.
- Full send snapshots and file bytes are saved in account-filtered IndexedDB before upload and retained until provider acceptance. Draft text stays on the server; draft file bytes are saved on the current device and survive reload there. Storage failures are explicit. Files are not synchronized across devices. Known failures restore editable snapshots; unknown outcomes require checking Sent.
- Stored and composer files share a content-based supported-type policy. PDF/raster/text/audio/video previews have bounded loading and a download fallback. HTML/SVG/Office/archive content is not rendered as executable content. Empty text has an explicit state and large text previews are capped at 256 KiB. Local object URLs are revoked on close/removal. Stored responses stream R2 bodies, enforce message/mailbox and quarantine checks, implement GET/HEAD and single HTTP ranges with 206/416, and use private no-store responses. CSP now permits the same-origin/blob frames and media required by these previews.
- Bounded `ical.js` parsing supports explicit ICS review from received or composer attachments, multiple event selection, UTC/TZID/all-day/floating dates, organizer/attendees, supported alarms, sequence updates, and cancellations. Floating times require a timezone; unsupported recurrence and ambiguous DST inputs are explained. Imports are private and deduplicate by user, UID, and organizer. Updates use sequence comparison and deliberate confirmation. Received updates also check the declared sender against the organizer; this is not a cryptographic sender-authentication claim. No automatic RSVP, invitations, external-resource fetch, or arbitrary-document calendar extraction is performed.

## Production evidence and delivery diagnosis

Read-only retained-job inspection found 27 accepted sends in the preceding week. Three-file job `job_KSJxoFiHXrVS6RnYsw_Js` stored 396,548 raw attachment bytes and reached provider acceptance in 21 seconds on its first attempt. Another two-file send, 39,834 bytes, took 24 seconds. The only retained non-sent job, `job_z7mzT8ehGE7mqkcL8Jsqs`, had zero attachments and `E_VALIDATION_ERROR`.

Those records do not establish an attachment-specific provider stall. The source did establish unbounded browser waiting, misleading success copy, oversized limits, and CSP blocking the PDF iframe. The targeted fix addresses these without introducing staged uploads. Safe stage logs now identify parsing, signature rendering, storage, reservation, publication, attachment loading, and provider duration; they omit bodies, file content, secrets, and recipient lists. Reproduction after deployment may still be needed to diagnose the original report conclusively.

The conservative budget follows [Cloudflare's current limits](https://developers.cloudflare.com/email-service/platform/limits/): 5 MiB for general recipients, with the higher allowance restricted to verified destinations. Provider acceptance is not proof of delivery to an inbox.
